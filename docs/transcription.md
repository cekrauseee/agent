# Recording transcription

`POST /api/transcriptions` requires a valid Better Auth session cookie and an exact `Origin` matching `BETTER_AUTH_URL`. Send `multipart/form-data` with exactly one file part named `file`; do not send a model, language, owner or conversation ID. A successful response is `{ "text": "original-language transcript" }`, with private/no-store caching. Text is forwarded unchanged, including whitespace and non-English characters, for a future composer to use.

Supported filename extensions are `mp3`, `mp4`, `mpeg`, `mpga`, `m4a`, `wav` and `webm`. Supply an appropriate audio MIME type (MP4/WebM/MPEG video MIME types are accepted for these containers). Generic binary or absent MIME types are accepted with a supported extension and recognized container header. Empty, very short, unknown-format and obvious non-audio files are rejected locally; OpenAI performs final container validation and audio decoding. Header recognition is not a complete media decoder.

The application caps the **entire multipart body at 4,000,000 bytes**, including multipart overhead, below OpenAI's documented 25 MB file limit. It counts actual streamed bytes even when `Content-Length` is absent or dishonest and stops oversized input before parsing FormData. Upload reading has a 30-second deadline. Any reverse proxy or deployment with a lower request limit must enforce that lower limit; reduce the application cap before hosting there. The current Docker runtime has no additional configured upload cap.

The endpoint uses the shared server-owned OpenAI SDK client and `audio.transcriptions.create`, with exactly `gpt-transcribe`, JSON output and the English prompt `Transcribe the speech in its original language.` It sends no language hint or translation request. Provider calls have a 60-second timeout and zero automatic retries. Requests reserve the same paid limits as conversation generation: 10 per user/minute, 3 active per user and 20 active globally, with release on success or failure. Validation and configuration checks occur before reserving paid work. These are request/concurrency bounds, not a financial spending guarantee.

The application stores neither audio nor transcripts, creates no conversation message and starts no assistant response. It logs no audio, transcript or provider error body. OpenAI processing/retention follows the provider's own policy. A disconnected upload is invalid; a disconnected provider request is aborted and its paid slot released, but a retry may incur another provider charge.

Errors use the shared `{ "error": "safe message" }` shape: authentication 401, untrusted origin 403, invalid multipart/audio or upstream decoding rejection 400, unsupported content type/format 415, oversized body 413, upload timeout 408, shared request/concurrency bound 429, unavailable configuration/provider access/rate limit 503, provider timeout 504 and other provider failures or invalid output 502. Shared infrastructure failures remain sanitized 500 responses.

`tests/transcription.test.ts` covers bounded reads (including dishonest lengths), accepted/rejected formats, malformed multipart, upload timeout, provider timeout, original-language forwarding and an authenticated route against isolated PostgreSQL with the official SDK's controlled HTTP transport. It verifies the exact provider fields, safe upstream errors, no automatic retries, paid release and chat/transcription shared concurrency. Run it with the local database URL as described in [Database](database.md); it performs no paid calls. Live multilingual recognition and account access to the model remain unverified without explicitly authorized credentials and spending.

API limits and original-language semantics follow the [official OpenAI file transcription guide](https://developers.openai.com/api/docs/guides/speech-to-text). This endpoint handles completed recordings only; microphone capture and Realtime voice are outside its scope.
